# Phase 2: Brain Core — Ingest Agent + 지식 그래프 + 시간 감쇠

> **Goal:** 저장을 "받아쓰기"에서 "이해하고 정리하기"로 바꾼다. 문서들이 관계(엣지)로 연결된 살아있는 그래프가 된다.
> **Prerequisite:** Phase 1 (워크스페이스 기반)
> **Output:** smart ingest 파이프라인 + 문서 그래프 + 버전 보관 + 시간 인식 검색

---

## 1. Purpose (목적)

인공두뇌와 단순 저장소의 차이는 **들어오는 정보를 기존 기억과 대조해 정리하는 능력**이다. 지금은 "오늘 A회사 면접 봤고 B 라이브러리 공부했다"를 넣으면 잡탕 문서 1개가 생긴다. 이 phase 후에는: 주제별로 분할되고, 기존 관련 문서와 엣지로 연결되고, 이미 아는 내용이면 기존 문서가 갱신(이전 버전 보관)된다.

## 2. Goals (목표)

1. 문서 간 관계(Edge)가 데이터 모델의 일급 시민이 된다 — raw JSON에 저장, Qdrant에 비정규화, reindex에서 생존.
2. Ingest Agent가 입력마다 신규/업데이트/분할/중복을 판단하고 실행한다.
3. 판단 실패 시 무조건 raw 저장으로 폴백한다 — 정보 유실 0.
4. 업데이트 시 이전 버전이 보관된다.
5. 검색이 시간을 인식한다 (감쇠 가중치 옵션 + 기간 필터).
6. 그래프 이웃 탐색이 API와 MCP로 노출된다.

## 3. Acceptance Criteria (달성 조건)

- [ ] 독립 주제 2개가 섞인 입력이 문서 2개로 분할 저장되고, 응답에 분할 사실이 명시된다.
- [ ] 기존 문서와 실질적으로 같은 주제의 새 정보 입력 시 새 문서가 아니라 기존 문서 업데이트로 처리되고, 이전 버전이 보관된다.
- [ ] 저장 시 유사 문서에 자동으로 엣지가 생성되며, 관계 타입이 판단되어 붙는다.
- [ ] `POST /ingest?mode=raw`는 에이전트를 우회해 기존과 동일하게 동작한다.
- [ ] LLM 판단이 실패(타임아웃/파싱 불가)해도 입력은 raw 경로로 저장되고, 응답에 폴백 사실이 표시된다.
- [ ] 이웃 조회 API가 depth 제한과 함께 동작한다 (depth=2에서 2-hop 문서 반환).
- [ ] reindex 후에도 엣지가 보존된다.
- [ ] 시간 감쇠 옵션을 켠 검색에서 동일 유사도일 때 최신 문서가 상위에 온다.
- [ ] 기간 필터(예: 특정 날짜 이후) 검색이 동작한다.
- [ ] MCP에 그래프 이웃 조회 tool이 추가된다.

## 4. Anti-Goals (하면 안 되는 것)

- 엣지 전용 그래프 DB 도입 — Qdrant payload + raw JSON으로만.
- 자동 문서 삭제/병합 실행 — 중복 발견 시 판단 기록만 남긴다. 삭제 실행은 Phase 5 Review Queue의 사람 몫.
- 버전 diff/롤백 UI — 보관만 한다. 복원 기능은 백로그.
- 엔티티 추출 고도화(사람/회사 노드화) — 문서 중심 그래프 유지. context graph 확장은 이후 단계.

## 5. User Scenarios

1. **분할**: 소유자가 하루 일기를 통째로 넣는다. "면접 후기"와 "라이브러리 학습 노트"로 분할되고, 각각 관련 기존 문서(이전 면접 기록, 해당 기술 문서)에 엣지가 붙는다.
2. **갱신**: "이사 준비 — 계약금 입금 완료"를 넣자 기존 "이사 준비" 문서가 갱신되고 이전 버전이 남는다. 응답: "기존 문서를 업데이트했습니다".
3. **중복 감지**: 거의 동일한 내용을 두 번 넣으면 두 번째는 중복으로 판단되어 스킵 또는 병합되고, 그 사실이 응답에 나온다.
4. **연결 탐색**: 에이전트(MCP)가 "A회사" 문서의 이웃을 depth 2로 조회해 면접 기록 → 준비 노트 → 관련 기술 문서까지 걷는다.
5. **폴백**: LLM 프로바이더 장애 중에도 저장 요청은 전부 성공한다 (판단 없이 raw 저장, 메타데이터에 표시).
6. **시간 인식**: "최근 근황" 검색에 감쇠를 적용하면 3년 전 문서보다 지난주 문서가 위로 온다.

## 6. Functional Requirements

### Edge 모델
- 방향성 엣지: 대상 문서, 관계 타입, 가중치, 생성 시각.
- 관계 타입: RELATED_TO, UPDATES, CONTRADICTS, REFERENCES, PART_OF (열거형, 확장 가능).
- 엣지는 문서의 raw JSON에 저장되고 인덱싱 시 summary chunk payload로 비정규화된다.
- 엣지 추가/제거 시 raw JSON과 Qdrant가 함께 갱신된다 (raw가 먼저, 실패 시 둘 다 반영 안 됨이 관측 가능해야 함).

### Ingest Agent
- 입력 → 관련 기존 문서 검색(유사도 상위) → LLM 판단 → 전략 실행.
- 전략: 신규 저장 / 기존 문서 업데이트(병합) / N개 분할 저장 / 중복 스킵.
- 각 전략 실행 후 관련 문서와의 엣지 생성 (관계 타입 LLM 판단).
- 응답에 전략, 영향받은 문서 ID들, 생성된 엣지 수, 폴백 여부가 포함된다.
- 판단 프롬프트는 중앙화된 위치에 두고 단위 테스트로 구조(필수 입력 포함 여부)를 고정한다.
- LLM 응답은 구조화 형식으로 파싱하며, 파싱 실패 시 재시도 1회 후 폴백.

### 버전 보관
- 업데이트 경로에서 이전 문서 상태가 워크스페이스별 버전 저장소에 남는다 (문서 ID + 타임스탬프 식별).

### 그래프 탐색
- 이웃 조회: 시작 문서, depth(기본 1, 상한 필수), 결과에 각 문서의 관계 경로 정보 포함.
- 순환 그래프에서 무한 루프 없이 동작 (방문 추적).

### 시간 인식 검색
- 워크스페이스 설정의 감쇠 강도(lambda)를 사용하는 opt-in 감쇠 스코어링.
- 생성 시각 기준 기간 필터 파라미터.

### API / MCP
- ingest 응답 확장(전략 메타데이터), 이웃 조회 엔드포인트, 수동 엣지 추가/삭제 엔드포인트.
- MCP: 이웃 조회 tool 추가, ingest tool 응답에 전략 표시.

### Frontend
- AddPage: 저장 결과에 에이전트 판단(분할/업데이트/신규/중복, 폴백 여부) 표시.
- BrowsePage 문서 상세: 연결된 문서 목록(관계 타입 표시) + 클릭 이동.

## 7. Data Requirements

- Document에 edges 목록 추가 (기존 필드 불변 — 하위호환 직렬화: edges 없는 기존 JSON도 로드 가능).
- Edge: 대상 문서 ID, 관계 타입, 가중치(0~1), 생성 시각.
- 버전 레코드: 원본 문서 전체 스냅샷 + 보관 시각.
- ingest 응답: strategy, document_ids, edges_created, fallback(bool), reason.

## 8. Constraints & Invariants

- **raw JSON이 항상 진실**: Qdrant payload의 엣지는 파생물. 불일치 시 raw 기준으로 reindex하면 복원된다.
- **정보 유실 금지**: 어떤 실패 모드에서도 입력 텍스트가 사라지는 경로가 없어야 한다.
- 분할 상한(예: 1입력 최대 5문서), 이웃 탐색 depth 상한, LLM 재시도 상한 — 모든 루프에 상한.
- 에이전트 경로의 LLM 호출 수는 입력당 상수 상한을 가진다 (판단 1 + 관계 판단 1 수준, 문서 수 비례 무한 호출 금지).
- 기존 인덱싱 파이프라인(`core/indexer.rs`)을 실행기로 재사용 — 저장 로직 중복 구현 금지.

## 9. Architecture Decision Points

| Decision | User's Choice | Notes |
|----------|--------------|-------|
| LLM 판단 응답 스키마 | 자율 | 구조화 파싱 + 실패 폴백만 보장 |
| 업데이트 병합 전략 (append/replace/merge) | 자율 | LLM이 상황별 선택하게 하되 전략이 기록될 것 |
| 유사도 임계값들 (관련 후보 0.7, 중복 0.9+ 등) | 자율 | 워크스페이스 설정으로 노출 권장 |
| 버전 저장 형식 | 자율 | 파일 기반 유지 |
| 엣지 가중치 산정 | 자율 | 초기값 단순해도 됨 (Phase 5에서 감쇠 재계산) |

## 10. Risks & Mitigations

- **리스크**: LLM 판단 지연으로 ingest 응답이 느려짐 → 후보 검색 결과 수 제한, 판단 프롬프트에 요약만 전달. 타임아웃 시 폴백.
- **리스크**: 잘못된 업데이트 판단으로 기존 문서 오염 → 버전 보관이 안전망. 중복/업데이트 판단 근거(reason)를 응답에 남겨 관측 가능하게.
- **리스크**: 엣지-payload 비정규화 불일치 → reindex가 항상 복원한다는 불변식을 테스트로 고정.

- [ ] 이웃 탐색 (depth 상한, 순환 안전) 및 테스트

## Notes

Ingest Agent의 품질(판단 정확도)은 프롬프트 튜닝 영역으로, 이 phase에서는 **구조와 안전장치**(분기·폴백·상한·관측 가능성)가 완성 기준이다.
