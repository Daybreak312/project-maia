# Phase 1: Foundation — 워크스페이스 시스템 완성 & 회귀 제거

> **Goal:** 반쯤 물려 있는 워크스페이스/인증 시스템을 API·MCP·프론트까지 끝까지 연결하고, 깨진 테스트 0개 상태를 만든다.
> **Prerequisite:** 없음 (main 브랜치의 현재 상태에서 시작)
> **Output:** 워크스페이스 2개 이상을 서로 다른 API 키로 격리 운영 가능한 백엔드 + MCP + 최소 관리 UI

---

## 1. Purpose (목적)

스토리지 레이어(DocumentStore, QdrantStorage)와 도메인 모듈(workspace, auth)은 이미 워크스페이스를 인식하지만, HTTP API·미들웨어·MCP·프론트가 연결되지 않아 실제로는 단일 공간처럼 동작한다. 이 phase는 이후 모든 기능(그래프, 에이전트, 커넥터)이 딛고 설 기반을 완성한다. 기반이 불안정하면 위 레이어 전부가 재작업된다.

## 2. Goals (목표)

1. 깨진 테스트 2개(`test_tokenize_mixed`, `test_bm25_scoring`) 원인 규명 후 수정 — 증상 덮기 금지, 토크나이저 회귀의 근본 원인을 고친다.
2. 모든 API 엔드포인트가 워크스페이스를 인식한다 (미지정 시 하위호환 동작).
3. API Key 미들웨어가 키별 워크스페이스 접근을 강제한다.
4. 워크스페이스와 API Key를 API와 관리 UI에서 생성/조회/삭제할 수 있다.
5. 교차 워크스페이스 검색이 설정 기반으로 동작한다.
6. MCP 클라이언트가 워크스페이스를 지정하거나 키 기본값으로 동작한다.

## 3. Acceptance Criteria (달성 조건)

- [ ] `cargo test` 전체 통과 (기존 실패 2개 포함 0 failed).
- [ ] 워크스페이스 CRUD API가 존재하고 admin 권한 키만 사용 가능하다.
- [ ] API Key 발급 API가 존재하고, 발급 응답에서만 평문 키가 노출되며 저장소에는 해시만 남는다.
- [ ] `personal` 워크스페이스 스코프 키로 `work` 워크스페이스 문서에 접근 시 403이 반환된다.
- [ ] 같은 문서 ID가 서로 다른 워크스페이스에서 충돌 없이 존재할 수 있다 (컬렉션 격리 확인).
- [ ] 워크스페이스 파라미터 없는 기존 형식 요청이 `default` 워크스페이스로 정상 동작한다.
- [ ] 교차 워크스페이스 검색: 검색 요청이 여러 워크스페이스를 대상으로 하면 결과가 병합·재정렬되어 반환되고, 각 결과에 출처 워크스페이스가 표시된다.
- [ ] MCP tool 호출에 workspace 인자를 넘기면 해당 워크스페이스로 라우팅된다.
- [ ] 프론트에서 워크스페이스 선택·생성, API 키 발급·폐기가 가능하다.

## 4. Anti-Goals (하면 안 되는 것)

- 키 만료/로테이션 자동화 — `expires_at` 필드만 존중하면 충분, 갱신 플로우는 범위 밖.
- 워크스페이스 간 문서 이동/복사 기능 — 백로그.
- 세션/쿠키 기반 웹 인증 — 프론트도 API 키를 사용한다 (기존 방식 유지).
- BM25 알고리즘 자체 개선 — 회귀 수정만. 검색 품질 튜닝은 Phase 3.

## 5. User Scenarios

1. **격리**: 소유자가 `personal`, `work` 워크스페이스를 만들고 각각 키를 발급한다. 회사 노트북 MCP 설정에는 work 전용 키를 넣는다. 회사 노트북에서 personal 문서는 검색되지 않는다.
2. **하위호환**: 기존처럼 마스터키(`MAIA_API_KEY`)로 워크스페이스 지정 없이 요청하면 default 워크스페이스로 동작한다. 기존 MCP 설정이 깨지지 않는다.
3. **교차 검색**: personal 워크스페이스 설정에 cross-workspace 허용 목록이 있으면, personal 키로 "A회사 관련 정보" 검색 시 work 문서도 함께 (출처 표시와 함께) 반환된다.
4. **키 수명 관리**: 소유자가 Admin UI에서 "아이패드" 라벨 키를 발급하고, 몇 주 뒤 목록에서 `last_used_at`을 보고 안 쓰는 키를 폐기한다.
5. **회귀 없는 검색**: "React 공부한 내용" 같은 한/영 혼합 쿼리에서 영문 토큰이 정상 매칭된다.

## 6. Functional Requirements

### 검색 회귀
- 토크나이저는 한글, 영문, 혼합 텍스트에서 모두 유의미한 토큰을 생성해야 한다. 영문 토큰 소실 회귀를 수정하고, 혼합 텍스트 케이스를 테스트로 고정한다.

### 인증/인가
- 요청의 Bearer 키는 다음 순서로 해석된다: 마스터키(전체 admin) → ApiKeyManager 조회(스코프 적용) → 불일치 시 401.
- 키의 권한은 read_only / read_write / admin 3단계. 문서 쓰기는 read_write 이상, 워크스페이스·키 관리는 admin만.
- 인증 성공 시 해당 키의 `last_used_at`이 갱신된다 (요청 지연에 영향 주지 않는 방식).
- `MAIA_API_KEY` 미설정 시 인증 비활성(로컬 개발 모드) — 기존 동작 유지.

### 워크스페이스 라우팅
- 모든 문서/검색/인제스트 엔드포인트는 워크스페이스 지정 수단을 가진다 (쿼리 파라미터).
- 미지정 시: 키에 바인딩된 첫 워크스페이스, 마스터키/무인증이면 `default`.
- 존재하지 않는 워크스페이스 지정 시 404와 명확한 에러 메시지.

### 워크스페이스 관리
- 생성 시 템플릿(personal/enterprise) 선택 가능, 생성과 동시에 Qdrant 컬렉션이 준비된다.
- 삭제 시 raw 문서·컬렉션·설정이 함께 정리된다. `default` 워크스페이스는 삭제 불가.

### 교차 워크스페이스 검색
- 워크스페이스 설정의 cross-workspace 허용 목록에 따라 다중 컬렉션을 검색하고 결과를 결합한다.
- 요청 키가 접근할 수 없는 워크스페이스는 허용 목록에 있어도 제외된다.
- 각 검색 결과 항목에 출처 워크스페이스 식별자가 포함된다.

### MCP
- 모든 기존 tool에 선택적 `workspace` 인자를 추가한다.
- 환경변수로 기본 워크스페이스를 지정할 수 있다.

### Frontend
- Navbar에 워크스페이스 선택 드롭다운. 선택이 모든 페이지의 API 호출에 반영된다.
- Admin 페이지: 워크스페이스 목록/생성(템플릿 선택)/삭제, API 키 목록(라벨·워크스페이스·권한·last_used_at)/발급(1회 평문 표시)/폐기.

## 7. Data Requirements

- ApiKey: key_id, 해시된 키, label, 접근 가능 workspaces 목록, 권한, created_at, last_used_at, expires_at(옵션). 평문 키는 저장되지 않는다.
- WorkspaceConfig: 기존 구조(patrol/parsing/search/connectors) 유지. cross-workspace 허용 목록이 search 설정에 포함된다.
- 검색 응답: 기존 필드 + 출처 워크스페이스.

## 8. Constraints & Invariants

- 기존 API 경로·요청 형식을 깨지 않는다. 새 기능은 추가 파라미터/새 경로로만.
- 워크스페이스 격리는 저장·검색·삭제 전 경로에서 보장된다 — 우회 경로가 하나라도 있으면 실패.
- 키 검증은 상수 시간 비교 또는 해시 비교로 타이밍 공격을 피한다.
- Qdrant 불가용 시에도 워크스페이스/키 관리 API는 동작한다 (파일 기반이므로).

## 9. Architecture Decision Points

| Decision | User's Choice | Notes |
|----------|--------------|-------|
| 교차 워크스페이스 결과 결합 방식 | 자율 | 기존 RRF 패턴 재사용 권장 |
| last_used_at 비동기 갱신 방법 | 자율 | 요청 경로 블로킹 금지만 지킬 것 |
| 프론트 상태 관리 | 자율 | 기존 패턴 유지, 새 라이브러리 도입 지양 |
| 미들웨어 구성 방식 | 자율 | axum 표준 패턴(Extension/State) 준수 |

## 10. Risks & Mitigations

- **리스크**: 미들웨어 교체로 기존 엔드포인트 전체가 영향받음 → 회귀 테스트를 먼저 작성하고 교체.
- **리스크**: 컬렉션 분리로 기존 default 데이터가 안 보이게 됨 → 레거시 마이그레이션 경로 검증 테스트 필수.
- **리스크**: 프론트 작업 범위 확대 → 기능 동작 최소선에서 멈춘다 (anti-goal 준수).
