# Phase 4: Connectors — 유입 파이프라인 & 지식 대량 적재

> **Goal:** 소유자의 지식이 사는 곳(로컬 마크다운 생태계)에서 Maia로 정보가 스스로 흘러들어오게 한다.
> **Prerequisite:** Phase 2 (Ingest Agent — 유입 판단의 실행 기반)
> **Output:** 커넥터 프레임워크 + 로컬 디렉토리 커넥터 + 대량 초기 적재 수단 + 관리 UI

---

## 1. Purpose (목적)

두뇌는 감각 기관 없이는 비어 있다. 소유자의 실제 지식은 OpenClaw 워크스페이스(`memory/*.md`, 데일리 노트, 크론 리포트, USER.md), 프로젝트 문서 등 **로컬 마크다운 파일**에 쌓이고 있다. 이 phase는 (1) 그 지식을 한 번에 쏟아붓는 수단과 (2) 이후 계속 자동으로 흘러들어오는 파이프라인을 만든다. 모든 유입은 Ingest Agent의 판단을 거쳐 분할·병합·연결된다.

## 2. Goals (목표)

1. 커넥터 프레임워크: 소스 등록, 주기 실행, 증분 수집, 중복 방지, 상태 관측.
2. 로컬 디렉토리 커넥터(레퍼런스 구현): 지정 디렉토리의 마크다운/텍스트 변경분을 주기적으로 유입.
3. 대량 초기 적재: 디렉토리를 지정하면 전체 파일이 Ingest Agent 판단을 거쳐 적재되고 진행 상황이 관측된다.
4. 재실행 안전성: 같은 소스를 다시 돌려도 중복 문서가 생기지 않는다.
5. Admin UI에서 커넥터 등록·상태 확인이 가능하다.

## 3. Acceptance Criteria (달성 조건)

- [ ] 워크스페이스 설정에 로컬 디렉토리 커넥터를 등록하면, 주기 실행 시 신규/변경 파일만 유입된다.
- [ ] 같은 파일이 변경 없이 재스캔되면 재유입되지 않는다 (증분·중복 방지).
- [ ] 파일이 수정되면 Ingest Agent의 업데이트 판단 경로로 들어간다 (신규 문서 난립 금지).
- [ ] 대량 적재 실행 시 파일 수백 개 규모에서 완주하고, 진행 상황(처리/성공/실패 수)이 관측 가능하다.
- [ ] 개별 파일 유입 실패가 전체 적재를 중단시키지 않고, 실패 목록이 남는다.
- [ ] 유입된 문서에서 출처(소스 식별자, 원본 경로)를 확인할 수 있다.
- [ ] 커넥터별 마지막 동기화 시각·결과가 API와 Admin UI에서 조회된다.
- [ ] 커넥터 스케줄러가 백엔드 기동 시 자동 시작되고, 실행 중 오류가 서버를 죽이지 않는다.

## 4. Anti-Goals (하면 안 되는 것)

- Notion/GitHub/Readwise 등 외부 SaaS 커넥터 — 백로그. trait 설계가 막지만 않으면 된다.
- 파일 watcher(실시간 감지) — 주기 폴링으로 충분. 실시간성은 요구사항 아님.
- 유입 파일의 양방향 동기화(Maia → 파일 쓰기) — 단방향 유입만.
- 바이너리/이미지 파싱 — 텍스트 계열(md, txt)만.
- MCP 서버를 커넥터로 감싸는 브릿지 — 백로그 (원 설계에 있었으나 로컬 디렉토리 커넥터가 실사용 요구를 충족).

## 5. User Scenarios

1. **초기 적재 (인공두뇌 부팅)**: 관리 에이전트가 OpenClaw 워크스페이스의 `memory/` 디렉토리를 대량 적재한다. 수백 개 데일리 노트가 Ingest Agent를 거쳐 주제별 문서로 정리·연결된다. 완료 후 "몇 건 처리, 몇 건 실패" 리포트를 확인한다.
2. **지속 동기화**: `memory/`와 `reports/`를 커넥터로 등록해두면, 크론 리포트가 새로 생길 때마다 다음 동기화 주기에 Maia로 흘러들어온다.
3. **수정 반영**: 소유자가 USER.md를 갱신하면 다음 주기에 해당 문서가 업데이트 경로로 갱신된다.
4. **상태 확인**: Admin UI에서 "마지막 동기화 10분 전, 신규 3건, 실패 0건"을 확인한다.
5. **장애 격리**: 깨진 인코딩 파일 하나가 있어도 나머지는 전부 유입되고, 실패 목록에 그 파일만 남는다.

## 6. Functional Requirements

### 커넥터 프레임워크
- 커넥터 공통 계약: 증분 변경분 조회, 소스 식별자 제공. 새 커넥터 타입 추가가 기존 코드 수정 없이 가능한 구조.
- 워크스페이스 설정에 커넥터 인스턴스 등록 (타입, 대상, 주기).
- 스케줄러: 워크스페이스별 커넥터를 설정 주기로 실행. 수동 즉시 실행 API도 제공.
- 동기화 상태 저장: 커넥터별 마지막 실행 시각, 커서, 결과 요약.
- 중복 방지: 문서에 소스 식별자(source + 원본 경로/ID)를 기록하고, 동일 소스 항목 재유입 시 신규 생성이 아니라 업데이트 경로로 보낸다.

### 로컬 디렉토리 커넥터
- 설정: 대상 디렉토리(복수 가능), 포함 확장자, 제외 패턴(glob).
- 증분 기준: 파일 수정 시각 + 마지막 동기화 커서.
- 파일 → 유입 단위 변환: 파일 경로·수정 시각을 메타데이터로 포함해 Ingest Agent에 전달.
- 대용량 파일 보호: 크기 상한 초과 파일은 스킵하고 기록.

### 대량 적재
- 지정 디렉토리 전체를 순회하며 유입하는 실행 수단 (형태는 자율 — API or CLI).
- 순차/제한 동시성 실행으로 LLM rate limit 보호. 진행 로그 실시간 기록.
- 완료 리포트: 처리/성공/실패/스킵 수 + 실패 상세.

### API / Admin UI
- 커넥터 목록·상태 조회, 등록/수정/삭제, 즉시 실행 트리거.
- Admin UI: 커넥터 카드(타입, 대상, 주기, 마지막 결과), 등록 폼, 즉시 실행 버튼.

## 7. Data Requirements

- 커넥터 설정: 타입, 대상 정의, 주기, 활성 여부 — 워크스페이스 설정 내.
- 동기화 상태: 커넥터별 마지막 실행 시각·커서·최근 결과 요약 — 워크스페이스 데이터 디렉토리 내 파일.
- Document 출처 메타데이터: 소스 타입, 소스 식별자(경로 등), 원본 수정 시각.

## 8. Constraints & Invariants

- 커넥터 실행은 서버 요청 경로와 격리된 백그라운드 태스크 — 동기화 중에도 API 응답성 유지.
- 스케줄러/커넥터의 패닉·오류가 서버 프로세스를 중단시키지 않는다.
- 대량 적재 중단 후 재실행하면 이어서 처리된다 (이미 유입된 항목은 중복 생성되지 않음).
- 소스 파일은 절대 수정/삭제하지 않는다 (읽기 전용).
- 민감 경로 방어: 대상 디렉토리는 명시 등록된 것만. 심볼릭 링크 순회로 등록 범위 밖을 읽지 않는다.

## 9. Architecture Decision Points

| Decision | User's Choice | Notes |
|----------|--------------|-------|
| 대량 적재 실행 형태 (CLI vs API+스크립트) | 자율 | 진행 관측 가능성만 보장 |
| 스케줄러 구현 (tokio interval 등) | 자율 | 신규 무거운 의존성 지양 |
| 파일→문서 매핑 (1파일 1유입 vs 분할 위임) | 자율 | 분할 판단은 Ingest Agent에 위임 권장 |
| 동시성 수준 | 자율 | LLM rate limit 고려, 설정 가능 권장 |

## 10. Risks & Mitigations

- **리스크**: 대량 적재 시 LLM 비용/rate limit 폭주 → 동시성 제한 + 진행 저장(중단 재개 가능) + 파일 수 상한 옵션.
- **리스크**: 데일리 노트처럼 계속 append되는 파일이 매번 업데이트 유입됨 → 소스 식별자 기반 업데이트 경로라 문서 난립은 없음. 빈도는 주기 설정으로 제어.
- **리스크**: Ingest Agent 품질이 대량 유입에서 노이즈 생성 → mode=raw 대량 적재 옵션 제공 (판단 없이 보관 우선).

## 11. Delivery Checklist

- [ ] 커넥터 공통 계약 + 등록 구조 (신규 타입 추가 개방성) 및 테스트
- [ ] 동기화 상태 저장·커서 관리 및 테스트
- [ ] 소스 식별자 기반 중복 방지 (재유입 → 업데이트 경로) 및 테스트
- [ ] 로컬 디렉토리 커넥터: 증분 스캔, 확장자/제외 패턴, 크기 상한 및 테스트
- [ ] 스케줄러: 주기 실행 + 수동 트리거 + 오류 격리 및 테스트
- [ ] 대량 적재 수단: 동시성 제한, 진행 관측, 실패 격리, 중단 재개 및 테스트
- [ ] Document 출처 메타데이터 및 테스트
- [ ] 커넥터 관리 API (목록/등록/삭제/즉시 실행/상태) 및 테스트
- [ ] Admin UI 커넥터 관리, `npm run build` 통과
- [ ] `contexts/architecture.md` 커넥터 구조 반영
